# Как запустить Sales Copilot у себя

Это версия Foundation: работают регистрация, вход, рабочее пространство и настройки бизнеса. Telegram, ИИ и полноценная CRM ещё не реализованы.

## Windows 10/11 — запуск одним файлом

1. Распакуйте **весь** архив проекта: запускать файл прямо внутри ZIP не нужно.
2. Дважды нажмите `START_WINDOWS.cmd` в распакованной папке.
3. При запросе Windows разрешите установку Docker Desktop. Если Docker попросит перезагрузку, перезагрузите компьютер и запустите тот же файл снова.

Файл найдёт Docker или запустит его установку через WinGet, дождётся Docker Engine, создаст `.env`, соберёт приложение, проверит подключение к БД/Redis и откроет регистрацию в браузере. **Отдельно устанавливать Node.js и вводить команды не требуется.**

Если WinGet недоступен, файл покажет официальный адрес Docker Desktop. Начальная настройка Docker/WSL, включение виртуализации и системные подтверждения выполняются на вашем компьютере; при необходимости launcher подскажет, что сделать, и завершится без удаления данных. Для проекта нужен режим Linux containers.

Для следующего запуска используйте `START_WINDOWS.cmd`; чтобы остановить приложение и сохранить данные — `STOP_WINDOWS.cmd`. При первом запуске нужны интернет и время на скачивание и сборку образов.

Команды Docker и повторяемость генерации настроек проверены в Linux cloud. Установку Docker Desktop через WinGet и сам `.cmd` ещё нужно проверить на настоящей Windows; факт установки на вашем компьютере пока не подтверждён.

## Ручной запуск: что установить

- Node.js 24 LTS.
- Docker Desktop с запущенным Docker Engine и Linux containers. На Linux подойдёт Docker Engine с Compose v2.

## Первый запуск

Распакуйте архив. Откройте терминал в папке `sales-copilot`, где находятся `package.json` и `docker-compose.yml`.

```bash
node scripts/init-env.mjs
docker compose --profile app up -d --build --wait
```

Первый запуск скачает зависимости и соберёт приложение. Устанавливать зависимости через `npm ci` на компьютере для этого способа не требуется: они устанавливаются внутри Docker.

На этапе `exporting layers` Docker сохраняет готовые образы: это не ошибка. Если этап долго не завершается, проверьте свободное место на диске и активность Docker в диспетчере задач. В обновлённой версии рабочие образы уменьшены: обновляйте `Dockerfile`, `.dockerignore`, `docker-compose.yml` и `apps/web/next.config.ts` вместе. Существующий `.env` сохраняйте; очистка томов БД для обновления не нужна.

После успешного запуска откройте в браузере адрес:

```text
http://localhost:3000/register
```

Создайте свой аккаунт. Общего логина и пароля нет. Пароль аккаунта должен содержать минимум 12 символов и занимать не более 72 байт.

Используйте именно `localhost`, а не `127.0.0.1`: адрес должен совпадать с настройкой `WEB_ORIGIN`.

Скрипт создаст локальный `.env` со случайными паролями базы и Redis. В архиве нет паролей или данных облачной среды. Сохраняйте свой `.env`: повторный запуск не меняет существующие пароли.

## Остановка и следующий запуск

Остановить, сохранив данные:

```bash
docker compose --profile app stop
```

Запустить снова:

```bash
docker compose --profile app up -d --wait
```

Не добавляйте `-v` к команде `down`: эта опция удаляет тома с данными.

## Если приложение не открылось

Убедитесь, что Docker Desktop запущен. Из папки проекта выполните:

```bash
docker compose --profile app ps -a
docker compose --profile app logs --tail=100 api web
```

Порты 3000, 5432 и 6379 должны быть свободны. Если они заняты другим приложением, остановите его либо настройте порты проекта. При обращении за помощью не отправляйте `.env`, cookies или пароли.

Если старая версия `START_WINDOWS.cmd` требует Linux, хотя `docker info --format '{{.OSType}}'` отвечает `linux`, режим Docker уже правильный. Скачайте обновлённый launcher и замените только `START_WINDOWS.cmd` в своей папке проекта. Сохраняйте существующий `.env`. Новая версия показывает строку `Docker Engine: linux` и отличает ошибку команды от настоящего режима `windows`.
